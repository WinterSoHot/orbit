# 任务引用知识库资料：候选设计

状态：用户已确认推荐方案（2026-10-07）。

## 目标与验收例子

用户新建“比较两篇论文的方案”任务，选择两份本地 PDF 的指定页面或批注，查看将发送的文字，选择 Codex 或 Qoder 后创建任务。执行器接收任务目标与同一份资料快照。交付中的有效来源链接可以返回知识库的对应页面；交付可存入知识库，继续保留来源。

Markdown 和已保存网页也可参与任务。继续交付时可以添加新的资料，并保留每轮实际发送的资料记录。仅选择资料不发起模型请求。

## 两种范围

1. 推荐：显式引用资料。选择器复用标题、标签、正文关键词筛选，用户决定发送哪些资料及 PDF 页面/批注；不建立全库索引或增加 embedding 服务。
2. 扩展：全库自动检索问答。在第一种能力之上建立 PDF 正文索引、检索排序和自动选取片段。覆盖更广，但增加索引更新、删除同步、检索质量与上下文预算等工作。

## 推荐方案的交互

- 新建任务和任务对话输入框提供“引用资料”，已选择资料以可移除的小卡片显示。支持搜索并查看所选内容。
- Markdown、网页引用已保存正文；长文由用户缩小摘录范围。不会默默读取未保存编辑。
- PDF 可选择页面范围，复用现有 PDF.js 在本机提取文字；也可选择已保存高亮、批注或备注。页码采用阅读器显示的从 1 开始的物理页码。
- 发送前展示来源、页码和文字量。扫描页或无法提取的页面明确提示，可改选批注/备注或粘贴摘录；首版不增加 OCR。
- 首版每次最多 8 个资料条目、PDF 最多提取 10 页，资料正文合计最多 32,000 Unicode 字符。超过限制要求缩小范围，不静默截断。
- 任务保留来源快照列表。点击来源优先打开原文；文档删除、版本变化或批注移除时仍可查看发送时的摘录，并提示原文状态。

## 数据与执行边界

- 来源记录包含引用 ID、文档 ID、标题、类型、文档版本、PDF 页码/批注 ID、摘录正文与捕获时间。PDF 页面文字由本机 PDF.js 提取；不上传 PDF 原件。
- 后端验证文档归属、删除状态、版本、引用身份和容量；Markdown/网页正文及已保存批注从本地知识库读取。PDF 提取结果按引用请求校验来源和大小，作为用户显式选中的输入。
- 在创建任务或提交补充时先持久化本轮资料快照，再入队。排队期间资料更新不会改变已提交输入；失败、重启、归档和导出保留快照。
- 一个共享的输入构造路径向 Codex 和 Qoder提供目标与来源编号、链接、正文。知识库文字标注为参考材料，不能作为权限或工具指令；沿用已有执行权限。
- 运行中补充资料仅对已支持 steer 的执行器开放；不支持时保留选择，待本轮结束后发送。未确认的补充不宣称执行器已采用。
- 未附资料的旧任务保持现有行为。持久化格式增加版本保护；旧记录升级兼容，旧程序拒绝覆盖新格式。

## 引用与回存

- 提示执行器在回答中引用提供的来源编号。程序只能验证引用是否指向本轮提供的资料，不能保证模型每项结论都正确归因。
- 交付可显示“本轮提供的资料”清单，与模型实际引用分开，避免把附件列表当成证据。
- 对话和交付预览复用 `orbit://document/<UUID>?page=N&annotation=<UUID>` 解析，导航前继续遵守编辑保存保护；无效链接不执行外部协议。
- 复用已有“存入知识库”，将交付与来源清单保存为独立 Markdown 副本，不自动覆盖原资料。
- 导出的 Markdown 保留内部文档链接；这些链接在 Orbit 内解析，不承诺在外部编辑器中打开。网页来源保留 HTTP/HTTPS 地址。

## 验证重点

- 两种执行器实际收到同一规范化资料内容；纯协议夹具不消耗模型额度。
- 队列等待时原文更新、引用后资料删除、版本冲突、容量超限、写盘失败、续交付和旧记录加载。
- PDF 页面文字、页码范围、空白/扫描页、批注跳转和来源回存；新建、运行中补充、结束后继续交付的可用性。
- 来源选择、正文预览、移除、键盘操作，以及 Light/Dark 和紧凑布局；浏览器预览不读取用户文件或启动执行器。

## 当前边界

全库自动检索问答、embedding、OCR、自动监听资料变化、跨任务 Chief、并行根任务与可写代码工作区不属于推荐的首版范围。
