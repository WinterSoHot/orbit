# 独立 Agent、并行分工与交付评审设计

用户要求完成此前建议第二、三项。用户的“继续”授权实施已审查设计，并采用此前推荐的包含编程交付范围。具体实现边界及验证记录见执行计划和 README。

## 核心流程

配置 Agent → 创建团队任务并制定分工计划 → 用户确认 → 子任务并行执行 → 父任务汇总 → 独立评审 → 用户验收。

独立 Agent 保存名称、职责、执行器和模型；复用现有 Codex/Qoder 目录。计划确认时冻结配置快照，修改模板不会改变已确认分工。父子关系限制一层，每个团队任务 1–3 个必需子任务，不增加 Chief 自动拆分。

子任务复用真实 Task、对话、资料引用、队列及显式交付契约。父任务汇总使用父 Agent 配置；评审由用户选择不同 Agent 身份执行，模型可相同。评审新建独立会话，只读接收冻结计划、验收标准和成果，返回通过、需修改或无法评审；执行失败不冒充评审结论。

## 调度与恢复

共享 Runtime 统一登记预留及实际运行身份，最多三个任务并行。准入在短生命周期临界区内完成容量检查、持久 claim 与登记；CLI 初始化和模型响应不持该锁。适配器按任务清理进程，不对其他运行调用全局空闲检查。同一任务／会话保持单一 writer，未确认退出或清理失败仍计入容量。

预留以 taskId/requestId/runId 绑定并覆盖完整启动过程。取消和关闭先记录意图，不以适配器暂时 idle 为由释放预留；启动线程交接前核对意图，已创建进程必须交接所有权并确认停止。只有确认未创建进程或清理完成才释放槽位；finish_claim 同时核对预留身份及取消状态。适配器只回收协议结束且进程停止已确认的 run，closed 单独不构成回收条件；启动、forget、归档和关闭统一遵守。

父任务等待子成果或用户时不占执行槽；汇总和评审运行时占槽。只有全部必需子任务成功并由 Store 接受正式交付，才允许汇总。失败、中断或缺少交付进入待介入，用户显式重试失败项；不默认采用部分成果。

Store 持久化阶段及逻辑步骤身份，整批创建分工并校验任务／存储容量，禁止重复创建汇总或评审。重启保留工作流并暂停恢复，不自动重跑。取消父任务先保存取消意图，撤销待启动项，再中断其活动运行；迟到结果可以留作记录，但不能继续推进。

正常 claimed 启动与重启后待核对 claim 分开处理，按 run 跟踪退出和失败。平台工作流字段由 Store 强制保留，正式交付与阶段推进在同一持久化事务中完成；actor 回调持有 run 锁时不反向调用运行协调层。旧 run 快照仍拒绝；取消当前 run 后可保留其原有有界对话记录，不扩大迟到回写权限。重启后的阶段补齐仅在用户恢复后进行一次。任何任务、成果或输入容量不足均停止推进并保留已有数据，不能删除受引用成果腾空间。

## 版本与交付门槛

计划确认绑定独立计划版本，不使用会因日志变化的 Task revision 代替。汇总绑定采用的子成果 ID 与内容版本；评审绑定汇总及来源集合；验收绑定同一待验收版本。修改来源或成果使后续汇总、评审及验收失效，旧版本仍保留。

评审使用任务专用严格提交结构 orbit-review：schemaVersion、submissionId、inputVersion、verdict（pass/changes/unable）、summary、findings。结构拒绝未知／重复字段，Store 根据可信当前 task/run 绑定评审身份并检验 inputVersion；普通文字不推进评审。每个 summary 至多 10000 字、至多 20 条 findings，每条至多 2000 字；整包至多 256000 UTF-8 字节且仍受完整最终输出上限。非评审任务禁止此提交；同一身份重复提交遵循交付收据幂等规则。

冻结成果按有序 ID、类型、名称和完整正文组成受限输入包，以不可变规范化输入快照的精确比较验证版本；重用资料输入传输，不塞入 12000 字用户 prompt。输入包（计划、验收标准及成果）合计最多 32000 Unicode 字、8 项资料，发送前核对大小和完整性，超限阻止启动而非截断。link 只冻结 URL，评审卡明确未获取目标内容，不能宣称链接目标已检查。评审只验证收到的完整材料。

拒绝计划返回编辑；评审要求修改或用户拒绝验收返回修订成果，修订后重新评审。需要改变分工时生成新计划并重新确认。活动工作流保护被引用任务与成果，避免删除后产生悬空引用。

沿用单份工作台存储、平台与 actor 时钟分离，新增平台所有字段不允许执行器快照覆盖。新增格式需要升级 schema 并兼容历史读取。所有真实任务仍计入现有 50 任务、8 MiB 存储及每任务 10 成果上限。

## 编程交付边界

本轮包含 Codex 独立 worktree 写任务，CLI 确认受限沙箱且 MCP 状态完整为空后才发送 turn；Qoder、协调和评审保持只读。平台以 native Git plumbing 捕获不可变提交与真实 Diff，保留对象引用及操作日志。不同分工只允许路径不重叠的叠加集成；重叠、二进制或不完整 Diff 阻止合并。人工验收后还需单独确认，仅 CAS 更新未检出的本地目标分支，不推送、不更新用户目录。外部 Git 不受平台排他控制，不能承诺全仓库锁定。

快照包含已跟踪及未被忽略的普通文件；ignored 真实目录可排除且不检查内部。遍历范围内先拒绝特殊文件，读取使用 nofollow FD，大小、数量、深度和时间均有界。全部数据导出包含可恢复 Git bundle；未捕获工作区内容不算正式交付。

## 验证

使用隔离存储和协议 fixture 验证并发上限、同会话 writer、原子创建、迟到回写、重启暂停、取消、部分失败、缺失交付、版本失效和重复推进。前端验证计划确认、分工进度、评审结论和验收卡片；不启动用户真实任务验证。按 AGENTS 执行架构前置审查、失败复盘和最终 Diff 核查。
