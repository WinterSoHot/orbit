# Orbit PDF reader

The existing PDF.js 6.4.299 legacy renderer now uses upstream PDFViewer, PDFLinkService and PDFFindController. Continuous pages, real selectable text, search, internal outline destinations, nearby-page thumbnails and expanded reading are available. More than 200 pages uses upstream page scroll mode; above 10000 pages is rejected. Each main canvas is limited to 2 million pixels / 4096 dimensions; upstream maintains its own page buffer (normally at least ten). This is not a global memory bound. Only five small thumbnails are mounted at once. No second search text index is built.

Highlights accept a single-page text selection. Coordinates are stored in PDF user space, including rotated/cropped pages; overlays use the current viewport's point transforms. Comments, colors and deletion use an independent reader CAS revision. The original attachment is never rewritten. Selected excerpts can be appended to the latest Markdown notes with an `orbit://document/<UUID>?page=N&annotation=<UUID>` link. Removed annotations fall back to their page. Scanned PDFs need OCR for selection/search; OCR and embedding annotations into exported PDFs are outside this change. Ordinary PDF export remains the original PDF; complete-data export includes reader metadata.

## Storage and saving

`Document.pdfReader` contains independent revision, page, zoom and annotations. Disk schema V3 rejects older writers; V1/V2 migrate on their next successful mutation. Every V3 record requires the `pdfReader` key, and malformed data keeps the source file protected. Up to 500 annotations, 256 rectangles per annotation, 10000 rectangles total and 16KiB each for selected text and comments. All reader metadata shares the existing 16MiB library limit. Coordinates must be finite, ordered and within +/-1e7; actual PDF page/bounds checks run in the reader.

Body and reader saves merge revisions independently. Navigating, changing document mode, library mutations and complete-data export flush queued work; synchronous freeze prevents new edits entering while these operations wait. Failed writes retain input, stop the queue and block lossy navigation; copy-unsaved-data and explicit resave are available. A confirmed reload can abandon local reader changes only after the latest saved state is read and validated; cancellation/read/bounds failures retain local input. Reload has its own lock and cannot release a parent mutation freeze. Reader failures do not stop Markdown autosaving; navigation failure reschedules canceled body timers. A CAS conflict is never blindly overwritten. Trash/restore advances reader revision even before a PDF has been read, rejecting pre-lifecycle writes after restore. Ordinary closing with an outstanding debounce is not a guaranteed last-instant save; normal navigation/export explicitly waits.

## Compatibility and resources

API import completes before viewer import because the viewer depends on `globalThis.pdfjsLib`. Main and worker retain core-js Promise/ArrayBuffer compatibility. WK13 additionally lacked native ReadableStream async iteration and AbortSignal.any; narrow adapters cover PDF.js behavior and cancellation cleanup. They are not claimed to implement every Streams/Abort standard edge case. Worker ESM fallback exports are preserved.

`npm run dev` and `npm run build` copy the installed package's CMaps, standard fonts, WASM files and annotation icons to ignored `public/pdfjs/`; builds fail on missing package files. These resources are bundled locally. CSP only adds same-origin fetch; remote connections, PDF scripting, form interaction, automatic links, internal editors and detail canvas are disabled. External PDF links are disabled; internal destinations remain available. `useWasm:false` avoids executable WASM CSP changes; specialized image encodings such as JPEG2000 are not included in the fixture coverage. The existing 8M source-image limit remains.

- 21 Node tests plus existing SSR checks; 94 Rust tests passed, 5 model smoke checks remain ignored. Reader CAS tests verify real atomic writes, reopen, full export, body independence, lifecycle invalidation including empty readers, malformed records, failed writes and overflow.
- Production TypeScript/Vite build passed. Final architect C passed; `npm run tauri -- build --debug --bundles app` produced the updated Orbit.app (76.26 MiB).
- Isolated visible WK13 production/CSP core viewer probe: two canvases, two text spans, one search match, cleanup completed. Stream tests cover normal/early/preventCancel/read-error/cancel-error and lock release; signal tests cover empty/duplicate/invalid sources, reason order and listener removal.
- IAB fixture passed search, outline navigation, 90-degree rotation with nonzero page origin, selection/highlight, 125% alignment against the corresponding Range rect, comments, Markdown excerpt, failed save retaining input/blocking close, explicit retry, read-only guards, nearby thumbnails and two unmount/reopen cycles. It uses memory transport; Rust tests separately verify persistence. No actual user PDF or library was modified.
- Production-build KnowledgeEditor fixture additionally verifies failed reader save → rejected navigation → retry → excerpt and notes autosave without ⌘S; CAS/capacity errors, canceled reload, read/bounds failure retention, latest-version reload, delayed reload preserving the parent freeze, and document-link insertion flushing pending comments or retaining failed comments without changing notes.

Entry and IPC worked. This is not counted as a pass or as proof of a product defect. The core WK probe above is a narrower successful check.
