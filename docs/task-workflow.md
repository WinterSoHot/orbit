# 任务工作台

任务对话始终显示目标、补充和交付版本。运行中的正文与审批也在同一对话中。Codex 等确认支持 steer 的执行器可接收运行中补充；不支持时保留草稿，发送按钮禁用。结束后，支持恢复的会话可发送补充并排队继续，旧版本保留。

看板列：待办（尚未启动）、进行中（执行或排队）、待介入（审批、失败核对、交付待验收）、已完成（最新交付已验收）。执行结束不等于用户验收。编辑正文和新运行会清除验收；归档需先验收且没有排队请求。旧归档继续可查看、导出和删除。

所有执行器共用一个 FIFO 队列，同时一个根任务。用户明确点击启动或发送续交付后才加入；可暂停/恢复队列、取消尚未执行的请求。失败/中断暂停后续任务。重启时排队请求默认暂停，核对后恢复。启动请求处于 claimed 且未确认时不自动重试；确认执行器 idle 后撤销，再明确重新发起。

队列、请求身份和验收保存在 workspace schema v2。读取旧 v1；旧程序拒绝 v2，不能降级写入。知识库格式不变；导出全部数据包含新增请求和验收记录。

## 验证

测试使用临时目录和内存 fixture，不调用用户真实模型任务，不修改用户任务/资料库。隔离页面：`tests/task-workspace.html`。检查了四列、验收移动、草稿切换、补充入队、发送禁用、暂停和 active steer 回调。SSR 和生产构建另外覆盖浏览器/归档/能力限制。

拖动和按钮触发同一命令；不允许任意修改执行状态。桌面窗口关闭原生文件拖入拦截（dragDropEnabled:false），导入资料继续使用选择文件对话框。自动化拖动产生了 dragstart/dragover/dragend，允许 drop，但未产生 drop 事件；尚未完成真实桌面原生拖放验收。按钮等价操作已检查。当前环境不支持桌面原生 UI 自动化，打包核验不等于真实模型端到端验证。
