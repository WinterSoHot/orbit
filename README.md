# Orbit · 个人 Agent 工作台

Tauri 2 + React + TypeScript + Rust 的本地桌面原型。支持调研、编程、写作任务；任务列表、动态 Agent 关系图、待介入、运行记录与 Markdown 交付；独立本地知识库支持 PDF、网页和 Markdown。

## 运行

已构建的 macOS 应用位于 `src-tauri/target/debug/bundle/macos/Orbit.app`（已生成本机调试版本）。本机测试环境：macOS 13.7.8 Intel、Node 24.21.0、Rust 1.98.0、Codex 0.160.0。

```sh
npm install --registry=https://registry.npmjs.org
npm run tauri dev
```

仅预览界面：

```sh
npm run dev
# 打开 http://127.0.0.1:1420/
```

本地应用构建：

```sh
npm run tauri build -- --debug --bundles app
```

这是未做开发者签名和公证的本地原型，未验证其他机器或操作系统的分发。

打包后的无窗口连接检查（不调用模型）：

```sh
env PATH=/usr/bin:/bin:/usr/sbin:/sbin src-tauri/target/debug/bundle/macos/Orbit.app/Contents/MacOS/orbit-agent-workbench --doctor
```

## 体验

- 首次打开为空工作空间；已移除交互演示及示例交付，旧演示记录不再显示。已有真实任务保留。
- 创建任务，选择调研、编程或写作，以及 Codex / Qoder 执行器；点击启动。审批、补充方向、中断、结果预览与导出可交互。
- 真正执行需要 Tauri 桌面 App，以及所选执行器已安装、已登录的 CLI。在设置中分别检查 Codex / Qoder 连接，然后新建任务并显式点击启动。
- 连接检查仅发 initialize，不发 thread/start 或 turn/start，不调用模型。真实任务会消耗 CLI 对应的模型额度。
- 每次真实启动先读取 `model/list` 的可见默认模型，再显式传给 `thread/start`，避免继承不兼容的模型别名；任务详情显示执行器返回的实际模型。目录不是账号权限保证，调用失败会显示有界、脱敏的错误详情。
- 真实模式同一时间只运行一个根任务。CLI 路径优先检查 `~/.local/bin/codex`、`~/.cargo/bin/codex`、Homebrew 安装路径，再使用 PATH。

## 权限与运行语义

- Codex 文件沙箱固定 `read-only`；拒绝权限提升和文件修改审批。MCP 工具配置来自本机 CLI，文件沙箱不等同于对远程服务副作用的隔离。
- 真实状态由 Rust 持有，前端仅消费投影。重复或过期信息请求不会重新发送；不自动重试副作用。
- “中断请求中”只有在执行器确认后变成“已中断”。确认超时或连接结束显示“需核对”；不承诺外部操作已撤销。
- 已结束的真实任务可点击“同步协作”，通过 CLI 历史恢复该轮 Agent 关系；仅执行 initialize 和 thread/read，不调用模型、不重跑任务，保留交付文档编辑。同步失败保留原图。
- 子 Agent 仅展示已观测关系。实际 spawn/parentThreadId 及 subAgentActivity 的真实线程 ID 和路径可建立父子关系，sendMessage 不创建父子关系。兼容新旧协作事件并按实际线程 ID 去重；缺失事件不会补造状态或进度百分比。子活动未携带正文或模型信息时不推测这些字段。
- 退出 App 强制尝试停止它拥有的进程组；主动脱离该组的进程不在此范围。清理未确认时记录事件并阻止新真实任务。重启保留历史，把在途运行标为需核对，使旧请求失效，不自动续跑。
- 执行结束与业务验收分开；Codex 输出是对话交付，是否满足目标需要核对实际内容与证据。

## 本地记录

Tauri AppData 下保存 `workspace.json`、`library.json`、`library-blobs/`、`runs/` 和 `exports/`；macOS 通常为 `~/Library/Application Support/local.orbit.agent-workbench/`。快照先写临时文件后原子替换；损坏记录保留且禁止覆盖。工作空间最多 50 项（含归档）；满额拒绝新建，需要先删除不需要的归档任务，已有记录不会自动淘汰，展示活动最多 100 条；每轮独立保留最多 2048 个子活动标识，超限提示关系图不完整并停止接纳新子活动，不淘汰旧标识。Agent 最多 64 个，单条协议消息最多 1 MiB。

浏览器仅预览空界面，不读取或写入旧 localStorage 演示数据，也不能创建或执行任务。桌面 App 中，交付物点击即打开 Markdown 预览，支持标题、列表、表格、代码块；切换“编辑”可修改源码，点击“保存”或 ⌘ / Ctrl S 写入本地记录。文档窗口关闭前会提示未保存修改；直接退出整个 App 时请先保存。只允许编辑已结束任务的交付物，单文档上限 256 KB（UTF-8 字节），旧内容冲突或写盘失败会保留草稿并提示。

下载使用已保存版本。设置 → 导出文件夹可选择本机文件夹，单份交付、归档和全部数据导出共用此位置，重启后保留；可恢复到默认 AppData/exports。文件夹失效时提示重新选择，不自动改存到其他位置。文档中的原始 HTML 不执行，图片显示占位文字，仅允许 HTTP/HTTPS 和页内链接。没有任意文件路径写入接口。

设置 → 导出全部数据会保存一份带格式版本和时间的 JSON，包含工作台当前保留的全部任务（含归档和不同执行器）、Agent 详情、运行记录、审批记录、补充对话、全部交付版本正文、会话引用、能力和导出设置。运行中可导出当时的一致快照，不中断执行。已提交的文档保存完成后才导出，保存失败则提示；尚未写入本地的编辑和聊天草稿不包含。知识库的已持久草稿、历史版本、标签、智能分组及 PDF 原件一并包含在 version 2 的 JSON 中，PDF 以文档 ID 为键保存为 base64 附件；知识库损坏或原件缺失时整份导出拒绝，避免遗漏。导出文件不会覆盖已有文件；源记录损坏时拒绝导出并保留原文件。此导出不包含外部 CLI 登录凭据、私有数据库或运行目录文件，当前未提供导入恢复功能。

## 对话

Codex 的公开消息按真实 item 独立累计并保存；进度与最终回复连续显示，工具步骤可展开查看状态和退出码。工具记录仅包含白名单元数据，不保存命令参数、工具输出、文件补丁或推理正文。已有任务仍可查看旧交付；新时间线从更新后的执行开始记录。

运行中可补充方向或点击“停止”；已中断、失败的有效会话也能继续，不要求先生成文档。Cmd / Ctrl Enter 发送，Enter 换行；输入法组合期间不会误发。阅读旧消息时新输出不会抢走滚动位置，点击“返回最新消息”恢复跟随。真实澄清请求仍通过选项和自定义回答卡片提交。Qoder 按已声明的能力使用现有输出和控制入口。

每个任务最多保留 256 条时间线记录、256000 个 Unicode 字符，每条正文最多 16000 字符；达到上限会明确提示，已有记录和交付文档保留。截断的消息不会替代完整交付，仍可打开文档。

## 检查

GitHub Actions 配置见 [.github/workflows/ci.yml](.github/workflows/ci.yml)。推送 `main`、提交 Pull Request 或手动运行时，CI 会执行前端测试、TypeScript/Vite 构建、Rust 库测试，并生成 macOS Intel 调试 App。构建包在 Actions 页的 Artifacts 中保留 7 天，不连接真实 Codex/Qoder 账号。

CI 使用 Node 24、Rust 1.98.0 与 `macos-15-intel`；应用最低系统版本仍为 macOS 13。ZIP 保留 App 的权限与元数据，采用 ad-hoc 签名，没有开发者签名或公证。

自动发布配置见 [.github/workflows/release.yml](.github/workflows/release.yml)。推送 `vX.Y.Z` 标签后，校验标签与 `package.json`、`package-lock.json`、Tauri 配置及 Cargo 项目版本一致，执行测试并构建正式版 App ZIP 和 DMG。成功后自动创建 [GitHub Release](https://github.com/WinterSoHot/orbit/releases)，附上两种架构共四个安装包、SHA-256 校验文件及自动生成的变更说明。发布权限仅授予测试通过后的发布任务。发布工作流使用 `macos-15-intel` 和 `macos-15` 原生构建，分别提供 Intel `x64` 与 Apple Silicon `arm64` 的 App ZIP、DMG 和独立校验文件；两个架构的构建与测试均通过后才发布。安装包仍采用 ad-hoc 签名，未做开发者签名或公证。

发布前同步上述版本文件并提交到 `main`，然后推送对应标签，例如当前版本：

```sh
git tag v0.1.2
git push origin v0.1.2
```

也可在 Actions 的 Release 工作流中选择已有版本标签手动运行；选择分支或版本不一致时会拒绝发布。已存在的 Release 不会覆盖，后续交付请使用新版本标签。

```sh
npm test
npm run build
MACOSX_DEPLOYMENT_TARGET=13.0 cargo test --manifest-path src-tauri/Cargo.toml --lib
```

较快的协议核心检查不需桌面依赖：

```sh
MACOSX_DEPLOYMENT_TARGET=13.0 cargo test --manifest-path src-tauri/Cargo.toml --lib --no-default-features
```

已验证一次真实最小调用：CLI 目录默认 `gpt-5.6-sol` → 相同实际模型 → `turn/completed` → 回答 `OK`，不调用工具、不重跑用户调研。完整调研任务、模型用量、子代理事件覆盖和取消外部命令的效果尚需真实运行验证。此原型默认不发起任何模型请求，不包含商业登录集成。

手动重现最小真实调用检查（会使用一次模型额度，常规测试默认跳过）：

```sh
MACOSX_DEPLOYMENT_TARGET=13.0 cargo test --manifest-path src-tauri/Cargo.toml --lib runner::tests::local_minimal_real_turn_with_catalog_default -- --ignored --nocapture
```

### 子 Agent 详情

已结束任务的“同步协作”会读取本轮已观测子 Agent 的会话历史，显示其文本输出和轮次数；点击“查看完整输出”以只读 Markdown 查看。子会话历史不被推定为根任务当前轮次的全部输出，也不会覆盖主交付。模型名称仅显示接口明确返回的值，当前 CLI 可能不提供。读取失败保留原输出并提示；每节点正文上限 64,000 Unicode 字符，超限明确提示并改为“查看输出”。读取只使用 initialize/thread/read，不启动模型。

### 已交付任务归档

执行结束且已有交付物的任务可点击“归档任务”，从日常工作台和交付列表移入左侧“归档”。归档保留 Agent 历史、运行记录和正文，可查看只读 Markdown、导出交付或确认删除；不能编辑或重新启动。执行器清理未确认时无法归档或删除。删除只移除工作台记录及内嵌正文，Codex 会话、运行目录和已导出的文件仍保留。归档/删除先持久化再提交，失败保留记录，迟到事件不会让已删除任务复活。

旧快照在加载时仅过滤 provider 为 demo 的任务，不直接重写文件；下次正常保存不再包含演示记录。未知执行器的合法历史保留；损坏记录禁止覆盖。

## 通过聊天继续交付

已交付任务底部的“任务对话”保存初始目标、补充信息和交付版本。填写补充要求后点击“发送并继续交付”，续接所选执行器的原会话并启动新一轮；原始目标不变，先前结果（包括本地已保存的编辑）保留，可分别预览、编辑和导出。归档只读，不能继续聊天。重新开始会建立新会话并清空本任务旧交付，界面会提示确认。

每个任务最多保存 10 份交付、10 次交付后补充，每次 2000 字。已接受但初始化失败的补充也保留并计入次数。未知状态不自动续接；外部会话若出现了较新轮次或仍在运行，也停止启动，避免误用上下文。补充历史表示已提交给工作台，不代表模型已经成功处理。

Codex 运行中补充会保存原文，并显示待确认、执行器已确认、已拒绝或确认未知。确认响应必须匹配发送时的 run / turn；执行器确认仅表示收到该轮输入，是否采用应在交付中核对。确认未知不自动重发。同一轮的多个最终回答会按 item ID 合并为交付，而非只保留最后一段；输出最多 64k 字符，超限带明确提示。运行中补充最多 20 条。

补充启动失败时，任务对话会显示具体报错；未启动新 turn 的失败补充可点击“使用上次补充内容”重新填入草稿，核对后手动发送。现有交付版本始终保留。

若原 Codex 会话被其他写入进程占用，工作台只在核对最后已完成轮次后复制历史到续接分支，聊天中明确标注；不抢占原会话。分支记录必须保存成功后才发送补充。

## 统一执行器

`Runtime` 统一管理任务分发、单根任务准入、持久化、交付、编辑、归档和删除；`Executor` trait 负责协议、能力检查与自有进程。后端执行器目录驱动选择器和设置页，任务创建后执行器固定，历史会话不会跨执行器续接。扩展步骤和边界见 [执行器架构](docs/executor-architecture.md)。

| 功能 | Codex App Server | Qoder ACP v1 |
| --- | --- | --- |
| 创建 / 执行 / Markdown 交付 | 支持 | 已接入协议，真实 CLI 尚未验证 |
| 交付后继续聊天 | 支持 | 本次握手确认 loadSession 后开放 |
| 运行中补充 | 支持 | 当前接入不支持 |
| 中断 | 支持，等待执行器确认 | 支持，等待 prompt 返回确认 |
| 子 Agent 历史同步 | 支持 | 当前接入不支持 |
| 编辑 / 归档 / 导出 / 删除 | 共用业务层 | 共用业务层 |

Qoder 使用 [官方 ACP 接口](https://docs.qoder.com/cli/acp)，本机需安装并登录 `qodercli` 或 `qoder`；优先检查 `~/.local/bin`、`~/.qoder/bin`、Homebrew 和 PATH。每次启动重新核对协议版本与能力。加载旧会话时保留原工作目录及任务归属，历史回放不生成新交付；恢复失败保留已有版本，不自动开替代会话。

Qoder 客户端仅声明任务目录内普通 UTF-8 文本读取，写入和终端能力关闭，工具权限请求拒绝。该限制不等于操作系统沙箱，不能保证 CLI 自身所有工具都经过客户端授权。首版不引入 Node sidecar；其 SDK 的实时补充和丰富子 Agent 事件不在本次 ACP 接入范围内。

新增执行器：实现 `src-tauri/src/executor.rs` 中的 trait，在 `runtime.rs` 的注册列表加入实例，输出归一化 Task 快照并遵守当前 runId / revision。能力默认关闭，握手后仅开放适配器已实现的功能。目录会自动出现在 UI；同一业务层处理交付与归档，无需增加 provider 分支。旧 Codex 记录兼容，未知 provider 的合法历史可查看和导出，执行明确拒绝。

本次新增 ACP 状态机、独立 stdio 进程和两轮交付夹具验证；夹具不是 Qoder 模型执行。本机在适配器搜索路径中未发现 Qoder CLI，真实初始化和模型交付尚未验证。

## 独立知识库

打开左侧“知识库”，导入本机 PDF、`.md`/`.markdown` 或 UTF-8 `.txt`，也可新建 Markdown。保存网页支持 HTTP/HTTPS 静态正文提取，并保留来源链接；登录后或依赖脚本的页面可取消提取、手动粘贴正文。网页以离线正文保存，不是完整网页归档。PDF 使用本地逐页画布阅读，支持翻页和缩放，超大图片可能省略；导出保留原件。PDF 不运行文档脚本，没有 OCR，搜索匹配标题、标签及独立备注。

在文档信息中编辑标题和标签；标签统一去除空白及开头 `#`、转为小写。智能分组保存类型、精确标签、标题/标签/正文关键词、最近更新条件，同时满足各项条件的文档会自动归集。选择空条件匹配全部。搜索与分组均不调用模型。

Markdown 和网页正文支持阅读/编辑，PDF 支持 Markdown 备注。输入后约 600ms 保存草稿、约 2s 自动提交正文，也可点击保存或 ⌘/Ctrl S。自动快照在 30 秒内合并，保留该段时间的第一份先前正文；手动保存和恢复独立备份，每篇最多 20 个快照。历史面板可预览和恢复，恢复前先持久化备份当前可见文字；写入失败拒绝恢复。重开呈现已成功持久化的草稿，崩溃前未写盘的输入无法保证恢复。切换文档、分组或离开知识库先保存，失败保留当前编辑器并停止自动重试，可复制草稿或手动重试。正常退出也只保证已经成功写入的内容。

复制或插入 `orbit://document/<UUID>` 文档链接，在知识库预览中可点击切换；显示出链和已提交正文的反向引用，重命名不影响链接。链接仅在 Orbit 文档预览内解析，尚未注册系统级 URL 协议。交付文档窗口的“存入知识库”创建独立 Markdown 副本，知识库后续编辑不改变任务交付。

知识库数据与执行器协议独立，Codex / Qoder 共用同一资料库。首版限 100 篇文档、50 个智能分组；单正文、草稿或历史快照 512KiB，元数据实际 JSON 总量 16MiB；单 PDF 20MiB、PDF 总量 64MiB。数量上限不保证能同时容纳所有最大文档。超限操作明确拒绝，原记录保留；PDF 源文件保持不变。只读损坏状态可查看错误，不自动覆盖源文件。当前未提供知识库删除、OCR、云同步、DEVONthink 数据库连接及导出数据导入。

实现与边界见 [知识库设计](docs/knowledge-design.md)。自动化测试使用临时文件和本机 HTTP 服务；界面验证使用临时内存桌面桥接夹具，不写入用户 AppData，不调用模型。原生文件选择器交互和完整 App 意外退出仍需桌面人工体验。
